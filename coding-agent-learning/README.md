# Coding Agent 任务闭环学习记录

## 1. 这一阶段解决什么问题

原有 `Agent.chat()` 已经能够让 LLM 多轮调用工具，但程序无法明确回答：

- Agent 现在是在分析、修改、测试还是修复？
- LLM 说“完成”时，最后一次修改真的通过测试了吗？
- 测试一直失败时，如何防止无限修复？
- Agent 是否可能读写指定项目以外的文件？

新增 `CodingTaskRunner` 不复制 Agent Loop，而是监听真实工具结果，将一次编码任务整理成可验证的闭环。

## 2. 主要代码

- `corecoder/agent.py`：增加 `on_tool_result` 事件，工具结果写入对话历史后通知任务跟踪器。
- `corecoder/coding_task.py`：任务状态、测试记录、最终报告、修复次数限制和工作区保护。
- `examples/coding_task_demo.py`：离线演示“测试失败 -> 修改 -> 再测试成功”。
- `tests/test_coding_task.py`：闭环的自动化验证。

## 3. 调用流程

```text
用户提交编码任务
        ↓
CodingTaskRunner 补充闭环要求
        ↓
Agent 调用 LLM 选择工具
        ↓
搜索/读取代码（ANALYZING）
        ↓
运行测试（TESTING）
        ↓ 失败
根据真实错误修改（FIXING）
        ↓
重新运行测试（TESTING）
        ↓ 成功
输出结构化报告（COMPLETED）
```

## 4. 完成判断

Runner 为每次成功的 `edit_file` / `write_file` 增加修改版本号。只有测试成功时的版本号等于最新修改版本，才认为 `verified=True`。

因此以下情况不会被误判为完成：

```text
先测试成功 -> 又修改代码 -> 没有再测试 -> FAILED
```

## 5. 安全边界

`CodingTaskRunner` 会为 `read_file`、`write_file`、`edit_file`、`glob` 和 `grep` 增加工作区路径检查。绝对路径或 `..` 解析后如果越过工作区，调用会被拒绝。

Shell 命令仍使用现有危险命令规则；操作系统级强隔离需要容器或独立沙箱，不在本阶段伪装已经解决。

## 6. 开发中遇到的问题

### 问题：修改已写入文件，第二次测试却仍然执行旧代码

**现象**：`calculator.py` 已从减法改为加法，但立即启动的 Python 测试进程仍返回减法结果。

**原因**：修改前后文件大小相同，且发生在文件时间戳精度的同一时间窗口内，Python 命中了上一轮的 `.pyc` 字节码缓存。

**解决**：离线演示的高频修改测试命令加入 `python -B`，禁止读写字节码缓存，保证每轮执行最新源码。

### 问题：在 pytest 中再启动 pytest 耗时异常

**原因**：外层回归测试再启动内层 pytest，会重复加载项目插件和测试环境，不适合这个小型闭环用例。

**解决**：闭环自测使用标准库 `unittest`，仍通过真实子进程和真实退出码验证修复，同时避免重复 pytest 初始化。

## 7. 测试覆盖

- 测试首次失败，修改后再次测试成功。
- LLM 声称完成，但最新修改未验证时返回 `FAILED`。
- 测试连续失败超限后有限停止。
- 工作区外的文件修改被拒绝。
